# Security Policy — Draft

This project is currently an architecture prototype and should not be treated as a production security boundary.

Security design is foundational rather than additive. See [`docs/08-security-threat-model.md`](docs/08-security-threat-model.md).

Before public implementation, the project should establish:

- a private vulnerability reporting channel;
- supported-version policy;
- signing/revocation model;
- threat-model review process;
- security-critical code ownership rules.

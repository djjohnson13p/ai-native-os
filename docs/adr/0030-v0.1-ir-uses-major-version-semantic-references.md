# ADR 0030 — v0.1 IR Uses Major-Version Semantic References

- Status: **Accepted for the v0.1 / Issue #17 spike**
- Date: 2026-09-15

## Context

AIOS IR examples use references such as `table.import@1`, while semantic contract records carry full versions such as `1.0`.

The previous schema permitted unversioned references and minor/patch selectors without defining deterministic resolution behavior. That would force the first validator to invent a SemVer policy.

## Decision

AIOS IR v0.1 semantic type/capability references use exactly:

```text
<semantic-id>@<major>
```

Examples:

```text
table.import@1
data.table@1
experimental.foo@0
```

Unversioned references and `@major.minor[.patch]` selectors are invalid in v0.1 IR.

Contract records continue to use full versions `MAJOR.MINOR[.PATCH]`.

An immutable Registry Snapshot MUST select at most one active contract for each `(semantic ID, major)` pair. Validation resolves the IR major selector through that snapshot; it does not query catalogs/network or choose a dynamically highest compatible version.

The exact resolution semantics are documented in `docs/67-v0.1-semantic-reference-and-version-resolution.md`.

## Semantic identity

The major selector remains part of the semantic hash.

The exact selected contract full version/content is attributable through the Registry Snapshot identity rather than substituted into the source IR hash.

Therefore exact validation evidence is the combination of semantic program hash + registry snapshot + IR/hash profile.

## Consequences

### Positive

- deterministic/simple v0.1 registry lookup;
- no hidden SemVer solver in trusted validator;
- programs survive compatible minor/patch contract updates through new snapshots;
- incompatible semantic change is explicit as a new major selector;
- missing version never silently means "latest".

### Costs

- exact minor/patch pinning is not expressible inside v0.1 IR;
- compiled/Skill reuse must retain registry snapshot identity when exact contract interpretation matters;
- registry snapshot construction must enforce one contract per ID/major.

## Compatibility impact

The AIOS IR and semantic capability-port schemas are tightened to major-only semantic refs. Existing checked-in semantic IR fixtures already use major selectors and remain compatible apart from separately resolved Task-ID cleanup under ADR 0029.

## Revisit condition

Add exact/range selectors only if real workloads require them and an explicit future IR-version ADR defines deterministic resolution/hash behavior.
